# ECO-humanoid BRUCE 能耗建模改进阶段

nullptr，当前项目主线是：把原 ECO（原仓库节能策略）中基于关节侧机械功率绝对值的能耗约束，升级为 BRUCE（机器人名称）电机转子轴端的能耗约束，并分析不同步态阶段下各关节电机的驱动、制动和反向机械功状态。

原始 ECO 能耗约束近似为：

$$
J_{\mathrm{old}} = \sum_j |\tau_j \dot q_j|
$$

当前第一阶段先做到电机转子轴端，不进入电池端模型。当前主指标使用 8 个驱动电机的转子端正向机械能：

$$
E_{\mathrm{rotor,pos,8}} = \sum_t \sum_{m=1}^{8} \max(P^{\mathrm{rotor}}_{m,t}, 0)\Delta t
$$

其中髋偏航两个关节暂时不进入 8 电机约束，但仍记录其正负机械能，方便后续分析。

### `cost_limit1` 与原 ECO 的区别

原 ECO 的 `cost_limit1 = 6000` 和当前短训练使用的 `cost_limit1 = 21.45` 不是同一物理量，也不是同一数值尺度，不能直接做大小比较。

原 ECO 使用的是 10 个关节侧机械功率绝对值：

$$
c_{\mathrm{old},t} = \sum_{j=1}^{10} |\tau_{j,t}\dot q_{j,t}|
$$

也就是把每个关节的正向驱动功率和反向机械功率都取绝对值后相加。这个定义有三个特点：

1. 它在关节侧计算，不在电机转子轴端计算。
2. 它覆盖 10 个关节，包括两个髋偏航关节。
3. 它使用绝对值，因此不能区分正向驱动和反向机械功，也不能单独分析制动或潜在回收能量。

当前主方法使用的是 8 个驱动电机的转子端正向机械能增量：

$$
c_{\mathrm{new},t} = \sum_{m=1}^{8} \max(P^{\mathrm{rotor}}_{m,t}, 0)\Delta t
$$

对应的回合指标是：

$$
E_{\mathrm{rotor,pos,8}} = \sum_t c_{\mathrm{new},t}
$$

它的特点是：

1. 它在电机转子轴端计算，更接近 BRUCE 耦合传动后的电机工作状态。
2. 它只约束 8 个驱动电机，两个髋偏航关节不进入主约束，但仍单独记录正负机械能。
3. 它只累计正向机械能，反向机械功不再被当作“消耗”直接加进主约束。
4. 它包含 $\Delta t$ 积分，因此当前 `cost_limit1` 的量级接近每回合转子端正向机械能，单位可按焦耳解释。

因此：

| 项目 | 原 ECO | 当前阶段 |
| ---- | ------ | -------- |
| 典型 `cost_limit1` | `6000` | `21.45`、`20.32`、`22.58` |
| 成本定义 | 10 关节侧绝对机械功率 | 8 电机转子端正向机械能 |
| 是否区分正负机械功 | 否 | 是 |
| 是否包含髋偏航主约束 | 是 | 否，髋偏航只记录不约束 |
| 是否适合分析制动/反向机械功 | 不适合 | 适合 |
| 数值是否可直接比较 | 不可比较 | 只和同一新定义下的基线比较 |

所以，`cost_limit1 = 21.45` 不是把原 ECO 的 `6000` 简单缩放得到的，而是根据 `rotor_positive_8` 下原始策略 0.1 m/s 固定评估基线计算出来的。当前固定评估基线中位数为 `22.5831`，`21.45` 表示希望外部评估相对基线约降低 5% 的转子端正向机械能。

需要特别注意：算法更新拉格朗日乘子时，直接比较的是随机化训练环境中最近 100 个完成回合的 `Train/mean_cost1`，不是固定评估的中位数。因此，`21.45` 目前同时承担“固定评估目标”和“训练成本上限”两个角色，但两者来自不同数据分布。阶段一可以用它验证约束方向是否有效；正式训练前必须统一或重新校准这两个统计口径。

## 阶段 5：短训练试验

状态：**短训练验证已完成到 `model_4000.pt`；固定 $v_x=0.1$ 外部评估通过，训练分布约束尚未收敛**。

短训练的含义：从已有 `model_3000.pt` 继续微调一小段，例如 100、200 或 500 个训练迭代，用来判断约束是否合理。

短训练不是最终论文实验，它的作用是排雷：

1. 检查机器人是否还能稳定走。
2. 检查 `Train/mean_cost1` 是否下降。
3. 检查 `Train/Lagrange1` 是否正常变大。
4. 检查速度跟踪是否明显变差。
5. 检查策略是否通过摔倒、原地踏步或减速来“假节能”。

### 短训练和评估的完整理解

短训练就是拿原来的策略权重模型，例如 `model_3000.pt`，作为起点，在新的能耗约束条件下继续训练一小段，而不是从零开始训练。

这里新的约束条件主要是：

```text
energy_cost_mode = rotor_positive_8
cost_limit1 = 21.45
```

也就是把原 ECO（原仓库节能策略）里的关节侧绝对机械功率约束，换成 BRUCE（机器人名称）8 个驱动电机转子端正向机械能约束。

短训练的基本流程是：

```text
原始模型 model_3000.pt
  -> 在新 cost_limit1 下继续训练约 200 轮
  -> 得到 model_3200.pt
  -> 继续得到 model_3400.pt、model_3600.pt、model_3800.pt、model_4000.pt
```

短训练不是最终正式实验，它的目的不是直接产出论文结果，而是快速判断：

1. 新约束会不会把机器人训坏。
2. `Train/Lagrange1` 会不会对超约束能耗有反应。
3. 训练中的 `Train/mean_cost1` 或 `rew_cost1` 有没有下降趋势。
4. 策略是不是靠摔倒、减速、原地踏步来假装省能耗。
5. 当前 `cost_limit1` 是否值得进入正式长训练。

评估就是拿短训练后保存出来的权重模型，例如 `model_3200.pt`、`model_3400.pt`、`model_3600.pt`、`model_3800.pt` 或 `model_4000.pt`，放到统一评估环境里跑 20 回合，统计它相对原始 `model_3000.pt` 基线有没有变好。

评估环境固定为：

```text
command_x = 0.1
command_y = 0
command_yaw = 0
terrain = plane
noise = off
randomization = off
num_eval_episodes = 20
```

这样做是为了公平比较。训练时环境更复杂，包含地形、噪声、扰动、延迟、参数随机化和 heading command（航向指令）；评估时必须关掉这些随机因素，否则不同 checkpoint（检查点）之间不好比较。

评估主要看：

1. 成功率和是否摔倒。
2. `mean_velocity_x` 是否保持在合理范围。
3. `distance_x` 是否明显下降。
4. `rotor_positive_energy_8` 是否低于原始基线。
5. `rotor_negative_energy_8` 和 10 关节正负机械能如何变化。
6. `phase_summary.csv` 中步态相位能耗分布是否改善。

最核心的通过标准是：`rotor_positive_energy_8` 低于原始 `model_3000.pt` 的基线 `22.5831`，同时速度和稳定性不能明显变差。

一句话总结：

```text
短训练负责“让策略在新约束下适应一下”；
评估负责“公平检查适应后的策略到底有没有变好”。
```

### 推荐短训练顺序

先跑 `21.45`：**已完成到 `model_4000.pt`，固定 $v_x=0.1$ 外部评估通过并出现单位距离能效平台期**。

再跑 `20.32`：**暂缓**。当前 `21.45` 已明显降低固定 $v_x=0.1$ 的评估能耗，但训练分布下 `Train/mean_cost1` 仍高于 `21.45`，不应立即继续加压。

最后跑 `22.58` 作为“几乎不压能耗”的对照：**暂缓**。当前优先任务是统一训练成本上限和固定工况评估的统计口径。

### 短训练通过标准

短训练是否值得进入正式训练，主要看下面几项：

| 检查项       | 通过标准                                    |
| ------------ | ------------------------------------------- |
| 成功率       | 20 回合中最好全部成功，至少不能明显低于基线 |
| 平均速度     | `mean_velocity_x` 不应明显低于 0.1 m/s      |
| 前进距离     | `distance_x` 不应明显下降                   |
| 正向转子能耗 | `rotor_positive_energy_8` 应低于 22.5831    |
| 拉格朗日乘子 | `Train/Lagrange1` 应对超约束有反应          |
| 行为质量     | 不能靠摔倒、拖步、站着不走来降低能耗        |

如果 `21.45` 能稳定降低能耗且保持速度，说明新约束有效。

如果 `20.32` 明显走坏，说明 10% 节能压力过强，需要放松阈值或延长微调。

如果 `22.58` 和基线几乎一样，这是正常的，因为它基本只是验证新训练管线不会破坏原策略。

当前 `21.45` 的判断是：

1. 稳定性已经通过。
2. `model_3200.pt` 未通过节能标准。
3. `model_3400.pt` 明显改善，但总正向转子能耗仍略高于基线。
4. `model_3600.pt`、`model_3800.pt` 和 `model_4000.pt` 均在固定 $v_x=0.1$ 下显著降低总正向转子能耗，并保持 20 回合零摔倒。
5. `model_4000.pt` 是当前总能耗最低且实际速度最接近 `0.1 m/s` 的候选模型；`model_3800.pt` 的单位距离能耗几乎相同，但速度稍高。
6. `model_3800.pt` 到 `model_4000.pt` 的单位距离能耗只改善约 `0.05%`，说明当前训练已经进入能效平台期。
7. 当前不继续训练到 `model_4200.pt`，保留 `model_3600.pt`、`model_3800.pt` 和 `model_4000.pt`。
8. 固定 $v_x=0.1$ 外部评估已经通过；训练侧 `Train/mean_cost1` 仍高于 `21.45`，不能表述为训练分布下的形式约束已经满足。

4. 回合转子端正向机械能。

## 阶段 8：论文结果组织

状态：**训练和评估数据齐全后执行**。

论文可以按下面逻辑组织：

1. 原 ECO 使用关节侧绝对机械功率，不能区分正向驱动和反向机械功。
2. BRUCE 存在耦合传动，因此关节侧功率不能直接表示每个电机的工作状态。
3. 本文先建立理想传动下的电机转子轴端机械功率模型。
4. 原始策略评估证明反向机械功确实存在，并且具有步态相位特征。
5. 新约束训练后，比较能耗、稳定性、速度跟踪和步态相位变化。
6. 明确限制：当前结果不是电池端能耗模型，不含电机效率、驱动器损耗、电池回收效率和热损耗。
