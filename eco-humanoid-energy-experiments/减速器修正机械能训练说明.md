# 减速器修正机械能训练说明

## 1. 新旧模型的区别

当前已有的 `rotor_mixed_8_alpha050` 使用：

```text
E_mix = E_g^+ + 0.5 E_g^-
```

其中负机械功仍然作为正惩罚加入训练代价，`0.5` 只是训练权重，不是回生效率。

新增的 `reducer_corrected_8` 严格按下式逐电机计算：

```text
E_m = sum_j(E_g,j^+ / eta_g,mot,j - eta_g,gen,j E_g,j^-)
```

- `E_g,j^+`：第 `j` 个传动电机通道的正机械能。
- `E_g,j^-`：第 `j` 个传动电机通道的负机械能绝对值。
- `eta_g,mot,j`：驱动方向的减速器效率，范围 `(0, 1]`。
- `eta_g,gen,j`：回生方向的减速器效率，范围 `[0, 1]`。

代码中的 `E_g,j` 对应 BRUCE 差动传动映射后的 8 个电机机械功通道。这个模型仍不是完整的电池端能耗模型，不包含驱动器损耗、铜耗、铁耗、待机功耗和电池充放电效率。

## 2. 效率参数

仓库和本地论文没有提供 `eta_g,mot`、`eta_g,gen` 的实测值。命令行必须显式传入效率，支持两种形式：

```text
--reducer_motoring_efficiency=0.90
--reducer_generating_efficiency=0.50
```

或者按运行时 8 电机顺序分别给值：

```text
--reducer_motoring_efficiency=0.90,0.90,0.88,0.88,0.90,0.90,0.88,0.88
--reducer_generating_efficiency=0.50,0.50,0.45,0.45,0.50,0.50,0.45,0.45
```

下面以统一的 `0.90/0.50` 作为算法试跑假设。它只能用于观察训练趋势，不能当作 BRUCE 的真实硬件效率结论。

## 4. 判断是否有效

至少同时比较原始 `model_3000` 和训练后 `model_4001` 的：

- 固定工况成功率、跌倒数、平均速度和速度误差。
- `reducer_corrected_energy_8 / distance_x`。
- `rotor_positive_energy_8 / distance_x` 和 `rotor_negative_energy_8 / distance_x`。
- 训练分布成功率、`cost1` 均值及其相对代价上限的偏差。

如果修正能量下降，但正机械能没有下降、负机械能显著上升，说明策略可能在利用回生项压低净代价，不能直接认定为真实节能。此时应降低 `eta_g,gen`、加入正功辅助约束，或升级为包含电机和电池损耗的模型后再训练。
